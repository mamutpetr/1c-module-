# Збирач даних з контролера Rayton

Кабінет контролера (`http://192.168.0.57/dashboard`) показує лише поточні значення й нічого не зберігає.
`collector.py` цілодобово записує їх у CSV і передає в базу сайту (Firestore). Так у вас накопичується власна історія.

## Звідки беруться дані

Кабінет зроблено на Node-RED (FlowFuse Dashboard 2.0). Значення надходять через Socket.IO
(`/dashboard/socket.io`, лише polling) приблизно раз на секунду:

| Показник (`topic`) | Що це | Одиниці |
|---|---|---|
| `POWER_CONTROL_SOLAR_GENERATION` | генерація СЕС | кВт |
| `POWER_CONTROL_PLANT_CONSUMPTION` | споживання підприємства | кВт |
| `POWER_CONTROL_GRID_CONSUMPTION` | мережа: **+** купуємо, **−** віддаємо | кВт |
| `POWER_CONTROL_ESS_POWER` | АКБ: **+** розряд, **−** заряд | кВт |
| `RT_DATA_ESS_SOC` | заряд АКБ | % |

Контролер рахує споживання як СЕС + мережа + АКБ; на записаних даних рівність виконується точно, звідси й знаки.
Одиниці ми визначили за величинами, а не за документацією.
Окремо надходить графік заряду/розряду АКБ по годинах на сьогодні й завтра. Скрипт зберігає його в `data/schedule.json`.

Лічильників енергії (кВт·год) кабінет не передає. Енергію рахуватимемо з потужності: кВт·год = Σ кВт × Δt.
Якщо контролер почне передавати новий показник, скрипт напише про це в консоль і додасть колонку в CSV.

**Скрипт тільки читає.** Він нічого не надсилає контролеру, тому змінити режим роботи станції не може.

## Запуск (будь-який комп'ютер у мережі контролера)

```bash
pip install -r requirements.txt
python collector.py                       # рядок кожні 5 с у data/РРРР-ММ-ДД.csv
python collector.py --interval 1          # щосекунди
python collector.py --url http://192.168.0.57 --out D:\rayton
```

Приклад `data/2026-09-29.csv`:

```
time,POWER_CONTROL_SOLAR_GENERATION,POWER_CONTROL_PLANT_CONSUMPTION,POWER_CONTROL_GRID_CONSUMPTION,POWER_CONTROL_ESS_POWER,RT_DATA_ESS_SOC
2026-09-29T16:28:40+03:00,34.326,26.67,-0.656,-7,96
```

Час записується з часовим поясом, щоб перехід на зимовий час не плутав дані. Обсяг приблизно 1 МБ на добу при записі кожні 5 с.
Excel відкриває файл через «Дані → З текстового/CSV-файлу».

Скрипт сам перепідключається, якщо зникне мережа або перезавантажиться контролер.
Поки даних немає, рядки не пишуться, щоб старі значення не записалися як нові. Тому в файлі видно реальні пропуски.

## Погодинний звіт як у старому моніторингу (`energy_csv.py`)

Окремий простий скрипт. Він пише `data/energy-trend-chart-1D-РРРР-ММ-ДД.csv` у тому самому форматі, що й експорт старого сайту:
ті самі колонки, UTF-8 з BOM, рядок на кожну годину з кВт·год.

```bash
pip install "python-socketio[client]"
python energy_csv.py                                             # http://192.168.0.57
python energy_csv.py --url http://192.168.0.57/dashboard/page4 --out D:\rayton
```

- Енергію скрипт рахує сам щосекунди з потужностей кабінету, бо лічильників кВт·год контролер не передає.
  «Заряд УЗЕ з СЕС» дорівнює тій частині заряду, яку в цю секунду не покрила покупка з мережі.
- Файл дня оновлюється щохвилини: завершені години плюс поточна, яка ще набирається. Після перезапуску скрипт продовжує з того, що вже є у файлі.
- Генератор, `DATA_106` і ціну контролер не передає, тому ці колонки порожні. Години, коли скрипт не працював, теж порожні.
- Поки файл відкритий в Excel, Windows не дає його оновити. Скрипт повідомить про це й запише файл, коли його закриють.

## Передача на сайт (Google AI Studio + Firestore)

Сайт на AI Studio працює в браузері й не може сам дістатися до контролера в локальній мережі.
Тому збирач записує дані в базу Firestore того ж проєкту Firebase, а сайт читає їх звідти й оновлюється сам (`onSnapshot`).

```
контролер --(локальна мережа)--> collector.py --(інтернет)--> Firestore <-- сайт AI Studio
```

1. **Увімкніть Firestore у застосунку AI Studio**: картка «Enable Firebase» або Settings → Integrations → Firebase Firestore & Auth.
   ID бази можна взяти там само або у файлі `firebase-applet-config.json`, поле `firestoreDatabaseId`.
2. **Отримайте ключ для збирача.** Відкрийте [console.firebase.google.com](https://console.firebase.google.com) і виберіть той самий проєкт.
   Далі ⚙ Project settings → Service accounts → **Generate new private key**. Збережеться JSON-файл.
   Ключ дає повний доступ до проєкту. Тримайте його тільки на комп'ютері зі збирачем: не вставляйте в код сайту й нікому не пересилайте.
   Надійніший варіант: створіть у Google Cloud Console → IAM окремий сервісний акаунт лише з роллю **Cloud Datastore User** і згенеруйте ключ для нього.
3. **Запустіть збирач:**
   ```bash
   python collector.py --firestore-key C:\rayton\key.json --firestore-db ID-бази
   ```
   CSV пишуться як і раніше: це локальна копія на випадок проблем із хмарою.

Структура даних описана на початку `cloud.py`. Коротко:

| Документ | Що в ньому | Оновлюється |
|---|---|---|
| `rayton_live/current` | `solar`, `plant`, `grid`, `ess` (кВт), `soc` (%), `time` | кожні 10 с (`--live-every`) |
| `rayton_live/schedule` | `items`: графік заряду/розряду АКБ | коли змінюється |
| `rayton_days/2026-09-29` | `minutes["14:05"]`: середні за хвилину; `totals`: кВт·год за день | щохвилини |
| `rayton_months/2026-09` | `days["29"]`: кВт·год за кожен день | щохвилини |

Енергія за день: `solar_kwh`, `plant_kwh`, `grid_import_kwh`, `grid_export_kwh`, `ess_charge_kwh`, `ess_discharge_kwh`.
Її рахує збирач щосекунди, тому купівля й продаж у мережу, заряд і розряд АКБ рахуються окремо.

Приблизно 11,5 тис. записів у Firestore на добу. Безкоштовний ліміт Firestore становить 20 тис. записів і 50 тис. читань на добу.
Кожна відкрита сторінка з живими даними читає документ раз на 10 с, тобто близько 8,6 тис. читань на добу, якщо сторінка відкрита цілодобово.

Якщо зник інтернет, хвилинні дані накопичуються в `data/cloud-pending.json`, а після відновлення зв'язку довантажуються.
Підсумки дня зберігаються в `data/cloud-totals.json` і не губляться після перезапуску.

## Автозапуск

**Windows:** скрипт запускається разом із комп'ютером, навіть без входу користувача.
Шлях до `pythonw.exe` покаже команда `where pythonw`. Команду нижче виконуйте в cmd від імені адміністратора.
Після `collector.py` допишіть ті самі параметри, що й при ручному запуску (`--firestore-key`, `--firestore-db`):

```
schtasks /create /tn "Rayton collector" /sc onstart /ru SYSTEM /tr "\"C:\шлях\до\pythonw.exe\" \"C:\rayton-collector\collector.py\""
```

**Linux / Raspberry Pi:** `/etc/systemd/system/rayton-collector.service`

```ini
[Service]
ExecStart=/usr/bin/python3 /opt/rayton-collector/collector.py
Restart=always
[Install]
WantedBy=multi-user.target
```

Потім виконайте `sudo systemctl enable --now rayton-collector`.

## Перевірка без контролера

`mock_controller.py` надсилає ті самі події з вигаданими значеннями. Він знадобиться, щоб розробляти сайт поза мережею контролера.

```bash
pip install aiohttp
python mock_controller.py                                  # http://127.0.0.1:8080
python collector.py --url http://127.0.0.1:8080 --interval 1
```
